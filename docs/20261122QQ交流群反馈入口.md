# QQ 交流群反馈入口开发方案

## 背景与目标

当前反馈页提供邮件、Discord 和钉钉三个渠道。面向国内用户时，Discord 的可达性和使用门槛较高，因此本次计划：

- 保留现有 Discord 公共 API 和发送实现以兼容已接入的宿主 App，但将相关 API 标记为 deprecated，并从反馈页渠道选择器中隐藏。
- 在反馈页增加“QQ 群”入口，用于展示宿主 App 注入的 QQ 群信息，引导用户加入交流群反馈意见和讨论 App 使用。
- QQ 群号和说明文字为必填配置，二维码图片为可选配置。
- 发布版本升级为 `0.2.6`，完成测试后提交代码、创建并推送 `0.2.6` tag。

## 需求范围

### 宿主配置

计划新增 `FeedbackQQGroupConfiguration`，集中承载以下信息：

- `groupNumber: String`：QQ群号，必填。
- `description: String`：页面显示说明，必填。
- `qrCodeImage: SwiftUI.Image?`：群二维码，选填。

`FeedbackConfiguration` 和 `FeedbackManager.configure` 增加接受上述 QQ 群配置的新接口。QQ群号使用 `String`，避免数字类型范围及可能的格式问题；二维码使用跨 macOS、iOS 的 SwiftUI `Image`，由宿主直接注入资源图片。

为兼容已经发布的调用代码：

- 保留 `discordWebhook` 属性、旧初始化方法、旧 `configure` 方法、`FeedbackChannel.discord` 及 Discord 发送实现。
- 对 Discord 相关公共 API 添加 deprecated 标记，并在弃用信息中指向 QQ 群配置或其他反馈渠道。
- 新接口要求显式传入 QQ 群号和说明文字；旧接口仍可编译运行，但 Discord 不再出现在反馈页。
- `FeedbackPayload` 的默认发送渠道由 Discord 调整为邮件，避免新调用继续默认依赖已弃用渠道。

### 界面变化

反馈页渠道选择器计划显示：

- 邮件。
- QQ 群（配置有效时显示）。
- 钉钉（配置了 Webhook 时显示）。

无论宿主是否仍传入 `discordWebhook`，Discord 均不再出现在渠道选择器中。

选择“QQ 群”时：

- 显示宿主注入的说明文字。
- 显示 QQ 群号。
- 提供“复制群号”按钮，并显示复制成功反馈。
- 配置二维码时显示二维码；未配置时不保留空白区域。
- 隐藏反馈内容、联系方式、系统信息、附件和“发送反馈”按钮，因为 QQ 群是交流入口而不是 Webhook 发送渠道。

选择邮件或钉钉时，继续显示现有反馈表单及发送按钮。

界面新增的标题、标签、按钮、状态、辅助说明和无效配置提示均使用包内本地化资源，不在 SwiftUI 代码中硬编码。宿主注入的 `description` 属于业务内容，由宿主负责按当前语言传入对应文字。

## 数据库与持久化

无数据库变更。

QQ群号、说明文字和二维码均由宿主 App 在 `configure` 时注入，仅保存在当前进程内存中，不写入 UserDefaults、文件或数据库。因此：

- 不新增数据表、字段或持久化 key。
- 不需要旧数据迁移。
- 旧版本升级后不会产生持久化兼容问题。
- 验证重点为重新配置后内存中的配置及界面是否正确刷新。

## 测试与验收计划

### 自动化测试

- QQ 群配置能保存群号、说明文字及可选二维码。
- 提供有效 QQ 群配置时，可见渠道包含 QQ 群。
- `discordWebhook` 即使存在，可见渠道也不包含 Discord。
- 未配置钉钉时仅显示邮件和 QQ 群；配置后增加钉钉。
- 旧配置接口仍可调用，保证源码兼容。
- `FeedbackPayload` 默认发送渠道不再是 Discord。
- 中英文新增本地化 key 均存在且可读取。

### 界面验收

- 简体中文下，QQ 群标题、群号、复制按钮、成功状态等无英文遗漏或混排。
- 英文下，同一界面无中文遗漏或混排。
- 有二维码时图片清晰显示，布局不会挤压群号和说明文字。
- 无二维码时不显示空白占位。
- 选择 QQ 群后不显示反馈输入框、联系方式、系统信息、附件和发送按钮。
- 切换回邮件或钉钉后，反馈表单恢复且可正常操作。
- Discord 不再出现在界面中。
- macOS 和 iOS 均能编译；复制群号使用各平台对应剪贴板实现。

## 风险与处理

- **弃用标记产生编译告警**：包内部继续使用 Discord 实现时应避免无意义的自引用弃用告警；测试仅在专门的兼容性用例中调用旧接口。
- **配置变化导致选择器状态失效**：配置更新后检查当前选择项；若已不可用，则切换到第一个可见渠道。
- **QQ 群不是发送渠道**：公共发送逻辑不得把 QQ 群当成 Webhook；界面在该模式下不构建发送 payload。
- **二维码尺寸差异**：使用限定最大尺寸、等比缩放和无障碍标签，避免大图破坏布局。
- **宿主注入文字的国际化**：组件只能保证自身固定文案双语完整；README 中明确要求宿主根据当前语言提供对应说明文字。
- **发布操作不可逆性**：推送前再次确认测试结果、提交内容和 tag 指向；若远端已存在同名 tag，则停止发布并检查，不覆盖远端 tag。
