# 公告强制确认（mustRead）

## 1. 需求背景

帮助中心目前已有公告能力：公告可以由宿主 App 在 `configure` 时注入，也可以通过 `remoteURL` 从远端 JSON 拉取，用户进入帮助中心后自行查看，入口小红点提示未读。

但升级后「必须让用户知晓」的重要变更（数据迁移、接口下线、收费规则调整等）没有强制触达手段：用户不主动打开帮助中心就完全看不到。本次需求为公告增加「必须阅读确认」标记，让重要公告在启动后强制展示一次，用户确认后不再打扰。

## 2. 需求定义与已确认决策

- 公告新增 `mustRead` 标记（Bool，默认 `false`）。
- `mustRead == false`：行为与现状完全一致，只在帮助中心内展示，用户看不看自便。
- `mustRead == true`：启动后若该公告未确认且未过期，强制弹出正式确认窗口；用户必须点击「我已知晓」才能关闭，不能下滑关闭、点外部关闭或按 Esc 关闭。
- 确认后**永久不再自动弹**，跨启动、跨升级都记住；公告仍保留在帮助中心，用户可自行查看。
- 确认后**同时标记为已读**，避免帮助中心入口一直挂红点。
- 已过期（`expiresAt` 已过）的 `mustRead` 公告**直接跳过**，不弹窗。
- 多条 `mustRead` 同时待确认时，**一个弹窗内列出全部**，一次确认，不连环弹窗。
- 远程 JSON 中的 `mustRead` **同样生效**；拉取失败不重试、不阻塞，下次启动拉取成功后再处理。
- 弹窗设计要正式：需要能显示一条或多条公告，视觉上是一个完整的「重要公告」对话框，而不是简单 alert。

## 3. 现有实现分析

- 数据模型 `SHCAnnouncementItem`（`HelpCenter.swift`）已有 `id / title / message / publishedAt / level / linkTitle / linkURL / isPinned / expiresAt`，自定义 `Decodable` 使用 `decodeIfPresent`，新增字段对旧 JSON 天然兼容。
- `SHCAnnouncementConfiguration` 承载本地 items、`storageKey`、`remoteURL`。
- `configure()` 后异步执行 `refreshRemoteContentIfNeeded()`；远程公告按 id 合并，远程覆盖本地同 id 条目。
- 已读状态 `readAnnouncementIDs` 存在 `announcementStorageKey` 对应的 `UserDefaults`，`resetReadState()` 清除。
- 帮助中心内公告是折叠卡片（`SHCAnnouncementRow`），点开即标记已读；没有「确认」语义。
- 现有展示入口：`SHCHelpButton`（macOS 独立窗口 / iOS sheet）、`SHCHelpNavigationLink`、`SHCVersionHistoryListView`；没有启动后自动弹窗机制。

## 4. 技术方案

### 4.1 数据模型

`SHCAnnouncementItem` 增加：

```swift
public var mustRead: Bool   // 默认 false
```

- `init(...)` 增加 `mustRead: Bool = false`，源码兼容。
- `CodingKeys` 增加 `mustRead`；解码用 `decodeIfPresent ?? false`；编码始终写入。
- JSON 字段名即 `mustRead`。

### 4.2 远程合并规则

远程公告按 id 覆盖本地。为避免「远程 JSON 未带 `mustRead` 时意外清除本地强制标记」：

- 远程条目**显式提供** `mustRead`（true 或 false）→ 以远程为准；
- 远程条目**没有**该字段 → 继承本地同 id 条目的 `mustRead`；
- 远程新增 id → 默认 `false`，除非远程显式写了 `true`。

实现方式：远程 JSON 除解码 `[SHCAnnouncementItem]` 外，再用一个轻量辅助结构提取 `id -> Bool?` 的显式标记表（不污染 `SHCAnnouncementItem` 的存储属性与 `Hashable` 语义），合并时按上表处理。

`mustRead` 公告与其他公告一样参与 `visibleAnnouncements`、排序、`isPinned` 和红点逻辑；区别只在「启动后是否强制弹窗」。

### 4.3 确认状态持久化

- 新增存储键：`"\(announcementStorageKey).mustReadAcknowledged"`，值为已确认公告 id 数组，与已读状态**分开存储**。
- 分开的原因：已读可以由用户进入帮助中心、点开卡片、或「全部标为已读」触发；确认只能由强制弹窗的「我已知晓」触发，两者语义不同。
- `configure()` 时读取确认集合，**不做裁剪**：远程特有的 `mustRead` 公告 id 在本地配置里不存在，裁剪会导致下次启动重复弹窗。
- `resetReadState()` 同时清除确认集合（调试/测试需要重新弹窗）。
- 公告 id 是身份标识：**不要改 id**，否则会被视为新公告重新强制确认。

### 4.4 Manager 新增 API

```swift
public var pendingMustReadAnnouncements: [SHCAnnouncementItem] // 未过期 ∩ mustRead ∩ 未确认，已排序
public var hasPendingMustReadAnnouncements: Bool
public func acknowledgeMustReadAnnouncements(_ items: [SHCAnnouncementItem]? = nil) // 记录确认 + 标记已读
public func consumeMustReadPromptIfNeeded() -> [SHCAnnouncementItem]?               // 同步领取，防止多窗口重复弹
public func prepareMustReadPromptIfNeeded(timeout: Duration = .seconds(5)) async -> [SHCAnnouncementItem]?
public private(set) var isConfigured: Bool                                          // 供修饰符在配置晚于视图出现时补弹
```

- `pending` 排序沿用 `sortedAnnouncements`（置顶优先、再按发布时间倒序）。
- `acknowledge` 对当前 pending 写入确认集合并调用 `markAsRead`，只影响弹窗中展示的公告。

### 4.5 展示时机与去重

宿主在根视图挂载：

```swift
WindowGroup {
    ContentView()
        .SHCMustReadAnnouncementPrompt()
}
```

- 视图出现时触发一次「准备 + 展示」：若配置了 `remoteURL` 且本次启动尚未拉取完成，最多等待 5 秒让本地与远程的 `mustRead` 在一次弹窗里合并展示；超时或失败就用现有数据展示，远程稍后到达的内容本次启动不再弹。
- 如果 `configure` 晚于根视图出现，修饰符监听 `isConfigured`，配置完成后补弹一次。
- 每次 App 启动**最多自动弹一次**；若弹窗关闭后又有新的 `mustRead` 到达，留到下次启动处理，避免用户操作期间被打断。
- 同一进程多窗口共用一个 manager 状态，通过「本次启动已弹过 / 正在展示」标记保证只弹一次。
- 由于 `mustRead` 可能来自远程，弹窗不依赖用户打开帮助中心；远程拉取成功后 pending 出现即触发。
- 宿主也可自行调用 `prepareMustReadPromptIfNeeded(timeout:)`（等待远程后领取）或 `consumeMustReadPromptIfNeeded()`（立刻领取）控制时机，再自行展示 `SHCMustReadAnnouncementView`。

### 4.6 弹窗 UI 设计

新增 `SHCMustReadAnnouncementView`（正式对话框风格，单条/多条共用同一容器）：

```
┌─────────────────────────────────────────────┐
│  [!]  重要公告                               │  头部：图标 + 标题 + 副标题
│       请阅读以下内容后确认                     │
├─────────────────────────────────────────────┤
│  ┌───────────────────────────────────────┐  │  可滚动内容区
│  │ [重要]  数据迁移说明                    │  │  每条公告一张卡片
│  │ 2026-11-23                             │  │
│  │ 从本版本开始...                         │  │
│  │ [查看详情 ↗]                            │  │  可选链接，打开浏览器
│  ├───────────────────────────────────────┤  │
│  │ [提醒]  服务地址变更                    │  │
│  │ 2026-11-20                             │  │
│  │ ...                                    │  │
│  └───────────────────────────────────────┘  │
├─────────────────────────────────────────────┤
│ 确认后将不再重复提示，你仍可在帮助中心查看。    │  固定底部操作区
│ [              我已知晓              ]        │  全宽主按钮
└─────────────────────────────────────────────┘
```

细节：

- 容器：iOS 用 `.sheet` + `.presentationDetents([.large])` + `.interactiveDismissDisabled(true)`；macOS 用 SwiftUI `.sheet`（系统 sheet，挂在宿主窗口上）。两端共用同一个视图。
- 头部：44×44 图标底块（复用 `SHCIconTile` 的 `.header` 规格），图标随级别取 `tintColor`；标题 `title3` 加粗，副标题 `body` 次要色。
- 内容区：`ScrollView`，卡片复用 `EDSGroup`；每条展示级别徽章、置顶徽章、标题、日期（`yyyy-MM-dd`）、正文（完整展示，不折叠）、可选链接按钮（`openURL`，不关闭弹窗）。
- 底部：固定操作区不随内容滚动；主按钮全宽、48pt 高，文案「我已知晓」；上方一行次要说明。
- 关闭：无关闭按钮、无取消按钮，iOS 禁下滑，macOS 拦截窗口关闭，只能点确认。
- 主题：颜色、间距、字体全部来自 `EDSTheme` 与 manager 的 `accentColor` / `unreadColor`，跟随深浅色与宿主强调色。
- 无障碍：弹窗标记为 modal；确认按钮有明确 label；正文支持 VoiceOver 顺序阅读。

## 8. 兼容性与风险

- API 兼容：只新增字段和 API，不改签名、不删 API；旧宿主不挂修饰符即无行为变化，属修订版本 `0.2.7`。
- JSON 兼容：旧远程 JSON 没有 `mustRead` 时按 `false` 处理，且不覆盖本地强制标记。
- 弹窗风险：确认弹窗是阻断式的，若必须阅读内容过长，用户可能反感；通过「一次列全部 + 可滚动 + 明确确认按钮」降低摩擦。
- 远程风险：远程 `mustRead` 依赖成功拉取，离线或失败时本次不弹，下次启动再试；这是已确认的取舍。
- 合并风险：远程显式写 `mustRead: false` 会关闭本地同 id 的强制标记，属预期行为，需在 README 写明。
- 多窗口风险：同一进程多窗口通过 manager 标记去重；弹窗挂在根视图，若宿主根视图重建，需保证「本次启动已弹过」状态仍在 manager 上。
- 回滚：删除 `.SHCMustReadAnnouncementPrompt()` 或回退版本即可；残留的确认键无害。

## 9. 验收标准

- `mustRead = false`：启动无弹窗，帮助中心行为与现状一致。
- 本地注入 `mustRead = true` 且未确认、未过期：启动后弹窗展示，只有「我已知晓」可关闭。
- 多条待确认：一个弹窗按置顶/时间排序展示全部，一次确认。
- 点确认后：记录写入 `UserDefaults`、公告标记已读；重启 App 不再弹；帮助中心仍能看到该公告。
- 已过期 `mustRead`：不弹。
- 远程 JSON 带 `mustRead: true`：拉取成功后弹窗；拉取失败本次不弹，下次启动成功后再弹。
- 远程同 id 未带 `mustRead`：继承本地值；显式 `false`：关闭强制。
- 帮助中心内点开阅读不等于确认；未确认仍会在下次启动弹。
- `resetReadState()` 后重新弹。
- 旧 JSON、旧宿主编译与行为不受影响；中英文文案齐全；macOS 与 iOS 17 构建、`swift test` 通过。
