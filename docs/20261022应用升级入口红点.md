# App Store 可升级版本入口红点

## 1. 需求背景

SwiftHelpCenter 已能在配置后查询 App Store 版本。当 App Store 版本高于当前 App 的 `CFBundleShortVersionString` 时，帮助中心顶部会显示“软件升级 / Update App”按钮，但帮助中心入口的小红点目前只响应未读公告和未读版本历史。用户如果没有主动打开帮助中心，就无法从入口感知已有可升级版本。

本次需求是在已有升级查询和跳转能力上补齐入口提醒：只要存在未读内容或 App Store 可升级版本，帮助中心按钮与导航入口都显示小红点。

## 2. 现有实现分析

- `SHCHelpCenterManager.hasUnreadContent` 表示未读公告或未读版本历史。
- `SHCHelpCenterManager.hasAppStoreUpdateAvailable` 表示 App Store 版本高于当前 App 版本。
- `SHCHelpButton` 和 `SHCHelpNavigationLink` 当前仅使用 `hasUnreadContent` 控制小红点。
- 帮助中心顶部的升级按钮已使用 `hasAppStoreUpdateAvailable`，点击后可打开 App Store 页面。

`hasUnreadContent` 的语义应继续保持为“未读内容”，不能把 App Store 升级状态混入其中，否则只有升级可用时也可能错误显示“全部标为已读”操作。

## 3. 技术方案

在 `SHCHelpCenterManager` 中增加统一的入口提醒状态，将以下条件做逻辑或：

- 存在未读公告或未读版本历史；
- App Store 存在更高版本。

`SHCHelpButton` 和 `SHCHelpNavigationLink` 统一使用该状态显示小红点。升级状态仍由现有 App Store 查询流程更新；查询完成后 `@Observable` 状态变化会触发 SwiftUI 刷新，不新增请求或轮询。

为防止后续回归，增加组合逻辑测试，覆盖无提醒、仅未读内容、仅可升级版本、两者同时存在四种情况。

## 4. 数据库与持久化

**无数据库变更。** SwiftHelpCenter 不使用数据库保存 App Store 升级状态。

**无持久化变更。** 可升级状态仍来自运行期 App Store 查询结果，不新增 `UserDefaults` 字段，不需要旧数据迁移，也不会改变公告和版本历史的已读记录。

## 5. 界面变化

- App Store 存在更高版本时，`SHCHelpButton` 右上角显示现有样式的小红点。
- App Store 存在更高版本时，`SHCHelpNavigationLink` 图标右上角显示现有样式的小红点。
- 打开帮助中心后，顶部继续显示“软件升级 / Update App”按钮。
- 没有未读内容且没有可升级版本时，入口不显示小红点。
- 颜色、大小、位置和动画均沿用现有 `SHCUnreadDot`，不新增视觉组件。

## 7. 兼容性与风险

- API 兼容：不删除或修改现有公开 API；旧调用方无需改动。
- 状态语义风险：保持 `hasUnreadContent` 不变，避免影响“全部标为已读”按钮。
- 网络风险：App Store 查询失败时沿用现有行为，不显示升级按钮和升级红点，不影响帮助中心其他内容。
- 地区风险：查询仍使用现有 Apple ID 和地区参数逻辑，本次不改变商店区域选择。
- 发布风险：Swift Package 版本由 Git tag 决定，需要确保 `0.2.4` 标签指向已通过测试的发布提交并成功推送。

## 8. 验收标准

- 仅有未读内容时，两个帮助中心入口均显示小红点。
- 仅有 App Store 可升级版本时，两个帮助中心入口均显示小红点。
- 两种提醒同时存在时，小红点正常显示且不重复。
- 两种提醒均不存在时，小红点隐藏。
- “全部标为已读”仍只在有未读公告或版本历史时显示。
- 帮助中心顶部升级按钮及 App Store 跳转行为不受影响。
- 单元测试、macOS 构建和 iOS 目标编译通过。
- `main` 与 `0.2.4` 标签成功推送到 GitHub。
