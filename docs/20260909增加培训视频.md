# 联系方式提醒与培训视频：需求分析和开发计划

日期：2026-09-09

状态：组件开发、EasyDesignSystem 依赖迁移与基础单元测试已完成；实际集成 App 的界面和交互由调用方验收。下述 API 已实现。

## 1. 背景与目标

依据 [组件定位与路线图](positioning-and-roadmap.zh.md)，SwiftHelpCenter 是面向 macOS / iOS App 的公共帮助中心与用户沟通组件。本次补齐两个场景：

1. 用户反馈时明确知道：不提供联系方式，作者将无法回复。
2. 帮助中心增加独立的“培训视频”板块，支持本地配置与远程 JSON 补充，默认显示一行，展开后自动换行。

设计遵循低接入成本、默认体验可用、兼容已有调用代码以及中英文国际化的原则。

## 3. 联系方式提醒

### 3.1 行为

当前占位文字仅说明“邮箱或其他联系方式（可选）”，未说明不填的后果。

建议改为：

- 输入框占位文字：**联系方式（选填，不填则作者无法回复）**。
- 输入框下方常驻、可换行的说明：**如需作者回复，请留下邮箱或其他可联系到你的方式。**

占位文字直接提醒用户；下方说明避免窄屏截断，也不会随输入而消失。

联系方式继续选填，允许不填直接提交，不增加二次确认弹窗。不限制只能填写邮箱。现有将联系方式拼入反馈消息的逻辑继续复用。

### 3.2 国际化

更新已有 `FeedbackView.contactPlaceholder`，新增 `FeedbackView.contactHint` 及对应常量。建议英文：

- Placeholder: `Contact info (optional; required for a reply)`
- Hint: `To receive a reply from the developer, please leave your email or another way to contact you.`

通过 `packageL` 从包内资源读取，辅助功能说明也使用本地化资源。

## 4. 培训视频交互

### 4.1 板块位置与职责

建议顺序：公告（如有）→ 快速入口 → 培训视频 → 版本历史 → 常见问题。

培训视频展示长期使用教程；版本历史中的视频链接继续保留，用于某次更新的说明。首版不引入分类、搜索、播放进度、内置播放器或未读标记。

### 4.2 展示规则

| 场景 | 行为 |
| --- | --- |
| 无有效数据 | 隐藏整个板块 |
| 数据可放入一行 | 显示全部，不显示展开按钮 |
| 超过一行 | 默认显示实际布局的第一行，标题右侧提供“查看全部（共 N 个）” |
| 点击查看全部 | 原地展开，全部 pill 按可用宽度自动换行，按钮变为“收起” |
| 点击收起 | 恢复显示第一行 |
| 点击 pill | 在系统外部浏览器打开对应网页 |
| 标题过长 | 单个 pill 不超过容器宽度，标题单行省略；辅助功能可读取完整标题 |

默认折叠状态由视图管理，首版不持久化。窗口缩放、设备旋转、字体或语言变化后，重新计算首行和溢出情况。展开状态不因正常远程数据到达而主动重置。

### 4.3 布局与可访问性

“一行”以实际宽度计算，不是固定前几个视频。`EDSFlowLayout` 本身不支持首行限制；培训视频 pill 还需单独处理超长标题。

建议新增可折叠流式容器，复用 pill 视觉样式。测量与排布使用一致的尺寸规则，折叠时仅让首行条目参与可见交互和辅助功能导航。不能仅固定高度裁剪完整列表。

交互 pill 应采用明确的 Button / Link 语义，支持键盘焦点、激活和 VoiceOver。复用或扩展 Design System 时，保持现有调用者的默认行为。

外链仅接受有效 HTTP / HTTPS 网页地址。实施时验证 macOS / iOS 的打开行为，特别是可能关联视频 App 的 URL；不能仅因使用现有 `openURL` 就认定一定进入默认浏览器。如平台存在限制，应在组件文档中明确实际行为。

## 5. 公共 API 设计

建议新增独立模型，使用稳定 ID，使视频更换地址后仍可按同一条目更新。

```swift
public struct SHCTrainingVideoItem: Identifiable, Codable, Hashable, Sendable {
    public var id: String
    public var title: String
    public var url: URL

    public init(id: String, title: String, url: URL)
}

public struct SHCTrainingVideoConfiguration: Sendable {
    public var items: [SHCTrainingVideoItem]
    public var remoteURL: URL?

    public init(
        items: [SHCTrainingVideoItem] = [],
        remoteURL: URL? = nil
    )
}
```

在 `SHCHelpCenterConfiguration` 中增加 `trainingVideos: SHCTrainingVideoConfiguration?`，初始化参数默认 `nil`，保持既有源码调用兼容。

调用示例（作为帮助中心配置的新增参数）：

```swift
trainingVideos: .init(
    items: [
        .init(
            id: "getting-started",
            title: "快速入门",
            url: URL(string: "https://example.com/videos/start")!
        )
    ],
    remoteURL: URL(string: "https://example.com/training-videos.json")
)
```

支持只传本地、只配置远程、本地与远程同时提供三种方式。示例中的标题是演示内容；真实多语言 App 应传入调用方完成本地化的标题。

现有 `SHCHelpVideoLink` 使用 URL 作为 ID，不直接用于该新模型，避免换地址后出现重复条目。

## 6. 远程 JSON 与合并规则

首版使用 UTF-8 JSON 数组，不引入多种包装格式：

```json
[
  {
    "id": "getting-started",
    "title": "快速入门（新版）",
    "url": "https://example.com/videos/start-v2"
  },
  {
    "id": "advanced-workflow",
    "title": "进阶工作流",
    "url": "https://example.com/videos/advanced"
  }
]
```

### 6.1 合并语义

- 本地有效数据立即展示，不等待网络。
- 按 `id` 合并，相同 ID 的远程条目更新标题和 URL，保留原位置。
- 远程新增条目按 JSON 顺序追加。
- 远程未列出的本地条目继续保留，远程不能删除本地保底数据。
- 重复 ID 只保留一条：首次出现决定位置，后续有效条目更新内容。
- 每次成功刷新以“原始本地数据 + 最新远程快照”重新合并，不能向当前展示数组持续累加。
- 远程独有条目从最新快照移除后，应从展示中消失；有效空数组意味着回到本地数据。

### 6.2 异常和加载

- 校验非空 ID、非空标题、有效 HTTP / HTTPS URL；本地与远程采用一致规则。
- 数组内无效条目跳过，不影响其他有效视频；无效远程条目不能覆盖有效本地条目。
- 整个文件格式错误、网络异常或非成功 HTTP 状态时保留当前内容。非空数组若全部无效，按无效远程内容处理，保留上次成功结果。
- 使用 `URLSession` 异步加载，建议远程配置地址使用 HTTPS。
- 接入现有远程内容刷新入口，请求去重，避免重绘反复请求。
- 提供显式刷新入口；自动请求失败后不在每次重绘中无限重试，但允许后续显式重试。
- 保存原始本地数据与远程成功快照；配置变化时重置对应状态，并用取消任务或配置代次隔离旧请求结果。
- 失败不弹窗打断使用；仅远程配置且无成功数据时隐藏空板块。

首版仅保存内存成功结果，不承诺跨启动离线缓存。只配置远程数据时，重新启动后若离线将无视频可展示；需要离线保底的调用方应提供本地数据。

## 7. 国际化要求

国际化是本次开发和验收的必需项。

### 7.1 组件自带文案

所有新增 UI 文案、辅助功能标签与提示必须通过现有 `packageL` 和 `Bundle.module` 读取，不使用宿主 App 的资源包，不在视图中硬编码中文或英文。

建议新增 key（最终名称与现有常量风格保持一致）：

| Key | 简体中文 | English |
| --- | --- | --- |
| `FeedbackView.contactHint` | 如需作者回复，请留下邮箱或其他可联系到你的方式。 | To receive a reply from the developer, please leave your email or another way to contact you. |
| `SHCHelpCenter.trainingVideos` | 培训视频 | Training videos |
| `SHCHelpCenter.viewAllTrainingVideos` | 查看全部（共 %ld 个） | View all (%ld) |
| `SHCHelpCenter.collapseTrainingVideos` | 收起 | Show less |
| `SHCHelpCenter.openTrainingVideoHint` | 在浏览器中打开视频 | Open video in browser |

数量使用完整的本地化格式串与匹配类型的参数，不能拼接“查看全部”与中文量词。上述英文采用不含单复数名词的表达；若后续改为包含 `video/videos` 的数量句，应增加适当的复数资源并验证现有查表路径兼容性。

### 7.2 调用方内容

- 视频标题属于调用方内容，组件按原文显示，例如使用 `Text(verbatim:)`，不能把标题当包内本地化 key。
- 本地标题由宿主 App 使用自己的资源包完成翻译后传入。
- 远程 JSON 首版使用单一 `title` 字段。需要中英文视频内容的调用方可按当前语言选择不同 JSON URL，并传入相应语言的本地数据。
- 不自动翻译远程内容，不隐式根据系统语言改写 URL，不新增多语言标题字典。
- 包内界面语言跟随现有 `SHCAppLanguageManager`；内容语言由调用方负责同步。切换内容语言时，调用方重新配置数据与 URL。
- 不同语言文件中的同一视频建议保持稳定 ID；重新配置后清除旧远程快照，避免旧语言内容混入。

### 7.3 布局与回归

验证系统语言、手动中文和手动英文模式，以及页面打开时切换语言。培训视频标题、展开/收起、联系方式提示和辅助功能说明都应更新，不能显示资源 key。

英文长文案、中文长标题、窄屏和大字体都要重新计算布局。完整视频标题应可被辅助功能读取。新增语言沿用包的现有资源回退机制。
